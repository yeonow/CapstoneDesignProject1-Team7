## 원본 데이터 재검증

- Windows의 TShark 4.6.10으로 채널 9의 PCAPNG 130개를 다시 읽었다. 적격 프레임 3,284개의 프레임 번호와 RSSI가 패킷 CSV와 일치했다.
- 15m 재측정을 잠정으로 선택했을 때 기존 준비 ZIP의 감사 CSV, 시나리오 1 잠정 CSV 및 적격 잠정 CSV, 시나리오 2 CSV가 모두 일치했다. 두 15m 후보는 민감도 분석으로 각각 재현했다.
- 같은 입력과 seed로 기본 분석을 다시 실행해 `report.json`의 바이트 단위 일치를 확인했다.
- 원본 캡처와 실측 CSV·파생 결과는 Git 제외 경로에 보관했다.

## 현장 확인 항목

실제 Raspberry Pi 5와 USB 동글에서 다음 결과를 기록해야 한다.

| 항목 | 현장 통과 조건 | 상태 |
| --- | --- | --- |
| 모니터 모드와 FCS | 전용 USB 동글만 전환하고 원래 모드로 복원. 대상 Beacon의 Radiotap/FCS와 채널 검증 성공 | 현장 확인 필요 |
| 핫스팟 채널 변경 | 시작 시 실제 채널 탐색 성공. 수집 중 변경되면 런 중단 및 원본 보존 | 현장 확인 필요 |
| 저전압·USB 분리 | 이상 감지와 중단 확인. 재연결 후 장치 재식별 | 현장 확인 필요 |
| SSH 독립 실행 | 별도 systemd 서비스가 SSH 종료 후에도 이어지고 완료 또는 실패 상태 조회 가능 | 현장 확인 필요 |
| 15m 재측정 | 당시 송수신기 위치와 장비 이동 여부를 실험 노트에서 확인 | 잠정 |
